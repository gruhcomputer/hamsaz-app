# بعد از هر انتشار، اینجا را به‌روز کنید

سه جا باید هم‌زمان عوض شوند. اگر یکی جا بماند، برنامه چیزی اشتباه به کاربر
می‌گوید.

| # | کجا | چه چیزی |
|---|---|---|
| ۱ | `app-config.json` → `update.latestVersionCode` و `latestVersionName` | همان عددی که در بازار آپلود کردید |
| ۲ | `app.html` → بخش «آخرین نسخه» | همان عددها، برای خواندن آدم |
| ۳ | `app.html` → جدول «تاریخچهٔ نسخه‌ها» | یک سطر تازه |

بعد `git push`. GitHub Pages چند دقیقه بعد فایل تازه را می‌دهد. برنامه‌ها
روزی یک بار آن را می‌خوانند، پس تا ۲۴ ساعت بعد همه خبردار می‌شوند.

---

## نسخهٔ اجباری

`minSupportedVersionCode` یعنی «هر بیلدی پایین‌تر از این، دیگر کار نمی‌کند».
کاربرهای آن بیلدها یک کارت قرمز غیرقابل‌بستن می‌بینند با دکمهٔ بروزرسانی.

**فقط وقتی بالا ببرید که نسخهٔ قدیمی واقعاً از کار افتاده باشد** — معمولاً
وقتی اینستاگرام چیزی را عوض کرده و resolver قدیمی دیگر نمی‌تواند بخواند.

> بالا بردن این عدد صرفاً برای اینکه «همه بروند روی نسخهٔ جدید» کار درستی
> نیست: کاربری که همان لحظه نمی‌تواند به بازار وصل شود، اپی در دستش می‌ماند
> که خودش کار می‌کرد و ما از کارش انداخته‌ایم. به همین دلیل کارت اجباری هم
> صفحه را قفل نمی‌کند و کاربر می‌تواند باز هم تلاش کند.

مثال — وقتی بیلد ۳ منتشر شده و بیلدهای ۱ و ۲ دیگر کار نمی‌کنند:

```json
"update": {
  "latestVersionCode": 3,
  "latestVersionName": "0.3.0",
  "minSupportedVersionCode": 3,
  "message": "اینستاگرام ساختارش را عوض کرده و نسخه‌های قبلی دیگر نمی‌توانند فایل را پیدا کنند."
}
```

`message` اختیاری است و جای جملهٔ پیش‌فرض را می‌گیرد. متن ساده، بدون HTML.

## وقتی ریلزها فقط عکس می‌دهند

یعنی اینستاگرام `doc_id` را چرخانده. **نیازی به APK جدید نیست** — مقدار تازه
را اینجا بگذارید:

```json
"graphqlDocId": "<مقدار جدید>"
```

بازار چند روز بررسی می‌کند؛ این راه همان روز جواب می‌دهد.

## ساده‌ترین راه: پنل مدیریت

به‌جای ویرایش دستی این فایل، پنل مدیریت را باز کنید:

```
https://gruhcomputer.github.io/hamsaz-app/instadl/
```

از گوشی هم کار می‌کند. پیش‌نمایش زنده دارد، خروجی‌اش همین `app-config.json`
است، و دکمهٔ «ذخیره روی سایت» مستقیم همین فایل را می‌نویسد (با توکن گیت‌هاب
که در `README.md` کنار همین فایل توضیح داده شده). دیگر `publish.bat` لازم
نیست.

بقیهٔ این سند برای وقتی است که بخواهید دستی ویرایش کنید.

## افزودن یک اپ به نوار معرفی

`promo.apps` را ویرایش کنید؛ ساختارش همان
`C:\code\instaDownloader\assets\promo\apps.json` است. خودشناسی از قبل با
`"enabled": false` هست — وقتی منتشر شد `true` کنید.

**هیچ پاداشی برای نصب ننویسید** (سکه، باز شدن قابلیت، برداشتن محدودیت).
کافه‌بازار «ایجاد مشوق برای نصب برنامه‌ها» را صریحاً ممنوع کرده است.

### تصویر برای هر تبلیغ

هر مورد می‌تواند کلید اختیاری `image` داشته باشد:

```json
{
  "id": "hamsaz",
  "package": "ir.amgroup.hamsaz",
  "title": "هم‌ساز",
  "pitch": "۳۰۰ پرسش گفت‌وگو برای پیش از ازدواج",
  "accent": "#6C4DF6",
  "image": "https://gruhcomputer.github.io/hamsaz-app/instadl/assets/promo/hamsaz.png",
  "enabled": true
}
```

- تصویر را در `assets/promo/` همین مخزن بگذارید.
- **باید با `https://` شروع شود** وگرنه برنامه نادیده‌اش می‌گیرد — اندروید ۹
  به بعد `http` ساده را مسدود می‌کند.
- اگر بار نشود، برنامه به حرف اول نام برنامه روی مربع رنگی برمی‌گردد. پس
  نبودِ تصویر هیچ چیزی را خراب نمی‌کند.

## آدرسی که برنامه می‌خواند

```
https://gruhcomputer.github.io/hamsaz-app/instadl/app-config.json
```

در `C:\code\instaDownloader\lib\main.dart` ثابت `kRemoteConfigUrl` همین است.
اگر مسیر عوض شد، **هر دو جا** باید عوض شود.

> این آدرس روی Pages سایت هم‌ساز است که از قبل روشن است، پس ۲۰۰ می‌دهد. اگر
> روزی ۴۰۴ داد **اشکالی ندارد** — `RemoteConfig` تمام‌عیار best-effort است و
> برنامه با مقدارهای داخل APK کار می‌کند. هیچ خطایی به کاربر نشان داده
> نمی‌شود.

GitHub Pages از ایران همیشه در دسترس نیست. به همین دلیل هیچ‌وقت چیزی را
**فقط** اینجا نگذارید که برنامه بدون آن از کار بیفتد.

## چرا JSON و HTML جدا هستند

`app-config.json` را برنامه می‌خواند، `app.html` را آدم. می‌شد یکی را از
روی دیگری ساخت، ولی آن وقت صفحه به جاوااسکریپت نیاز داشت — و قاعدهٔ این
سایت (مثل سایت هم‌ساز) این است که هیچ جاوااسکریپت، ردیاب یا فونت خارجی
نداشته باشد تا روی هر اتصالی باز شود. پس دو جا دستی هماهنگ می‌شوند، و جدول
بالا یادآورش است.
